# docx-paragraph-polish：校正段落文字（Word 修订模式）

把一份 .docx 的正文段落逐段改写得更正式、规范、流畅，改写结果以 **Word 修订标记**（w:ins 插入 / w:del 删除）直接写入 OpenXML，产出副本；用户在 Word 或 WPS 中打开后可逐条接受或拒绝。

本 skill 移植自 WordTools 项目 SmartWriting 模块的「校正全文段落」功能：段落筛选、字符级 diff 修订写入、改动门槛规则与原实现一致；但写回不依赖本机安装 Word/WPS（纯 OpenXML），修订标记在 Word 与 WPS 中均正常显示。

## 环境要求

- Python 3.8+，带 python-docx、lxml（DSH 捆绑 Python 已含）。
- 无需安装 Microsoft Word 或 WPS。

## 工作流程（四步）

### 第 1 步：确认模式

先问用户（或从话术中推断）选哪档，不要默认替用户决定：

| 模式 | 说明 | 改动上限 |
|------|------|---------|
| **润色**（默认） | 只改字词表达：更正式、规范、流畅。不动句序、不拆合句。 | 净改动 ≤ 60%，超过跳过该段 |
| **逻辑重构** | 段落逻辑确有问题时允许重排句序、拆分/合并句子、用连接词显化因果。 | 净改动 ≤ 95%（硬顶），超过跳过该段 |

若文件可能被单位透明加密（打不开/乱码/提示损坏），提示用户先走 `decrypt-office-pdf` skill 解密。

### 第 2 步：提取正文段落

```bash
python <skill目录>/scripts/extract_body_paragraphs.py "<docx路径>" ["<输出json路径>"]
```

脚本自动排除（与原 BodyParagraphFilter 规则一致）：标题（大纲级别/标题样式/编号/章节模式）、表格内段落、图名/表名、含图片/形状/域代码的段落、空段落。默认输出 `<docx同目录>/<文件名>-paragraphs.json`，元素形如 `{"id":1,"paraIndex":3,"text":"……"}`。

### 第 3 步：逐段改写（由你完成，不调外部 API）

读取 paragraphs.json，**对每一段原文按下面的规则改写**，产出 rewrites JSON。

改写硬性约束（两种模式共同的红线，违反任何一条都会导致该段被跳过或污染文档）：

- 保持原意不变；**已有的数字、参数、地名、标准编号、工程名称一律原样保留，不得修改或替换**。
- 输出必须仍是**单个自然段的纯文本**：不得含换行符、列表符号、Markdown 标记；不得增删段落数。
- 不得新增原文没有的事实性内容（新数据、原因、依据、结论、专业判断）。
- 原文已足够规范时**原样输出该段**（脚本判无差异自动跳过，无需强行改）。

**润色模式**要点：只做字词级润色使表述更正式、规范、流畅；保守修改，改动幅度尽量控制在 30% 以内（上限 60%，超过会被脚本跳过）。

**逻辑重构模式**要点：若段落确有逻辑问题（句序不当、因果缺失、句式杂糅），可重排句序、拆分/合并句子，用连接词（“因此”“由于”“进而”“尽管”等）显化**原文已隐含**的逻辑关系；逻辑已通顺则只做字词润色。绝不可凭空补出原文未给出的理由或结论。

输出文件 `rewrites.json`（与 paragraphs.json 同 id 对应，`paraIndex`/`original` 必须从 paragraphs.json **原样复制**，不得手打）：

```json
[
  { "id": 1, "paraIndex": 3, "original": "……", "newText": "……" }
]
```

写完后自检：每条 newText 中不得出现换行；抽查数字、单位、标准编号与 original 逐字一致。rewrites.json 需包含全部段落（无需改动的段 newText 填原文即可，脚本自动判定无差异）。

**长文档并行改写（默认策略）**：段落 ≳60 段或总字数 ≳1.5 万时，把 paragraphs.json 按**累计字数均分**成 4–6 个分片文件（paragraphs_partN.json），每片派一个 subagent 并行改写（subagent 的 prompt 必须完整复制上面的红线约束和输出格式，指明读哪个分片、写哪个 rewrites_partN.json、UTF-8 无 BOM）。全部完成后父代理统一合并校验，任何一项不过即打回对应分片重做：

1. id 集合与该分片完全一致（无缺失/重复/跨片）；
2. 每条 original 与 paragraphs.json 的 text **逐字一致**（防手打错位）；
3. 每条 newText 无换行、非空。

短文档（≲60 段）不值得派发开销，直接由父代理自己改写。

### 第 4 步：以修订模式写回

```bash
python <skill目录>/scripts/apply_track_changes.py "<docx路径>" "<rewrites.json路径>" [polish|logic] ["<输出docx路径>"]
```

脚本行为：

1. 复制原文档为输出文件（默认 `<原名>-修订.docx`，**原文档不动**）；
2. 逐段做**字符级 LCS diff**：删字写 `w:del`（delText）、增字写 `w:ins`，未改动部分原样保留（含原格式）；修订作者标记为 `AI校正`；
3. 净改动占比超门槛（润色 0.6 / 逻辑重构 0.95，硬顶 0.95）、改写含多段、段落内容与提取时不一致的段落**自动跳过**并在摘要中列明原因；
4. 打印统计并输出 `*.summary.json`。

### 收尾汇报

向用户报告：总段数、写入修订 N 段、跳过 M 段（跳过原因分组）；输出文件路径；提醒用户在 Word/WPS 中打开后用「审阅→修订→接受/拒绝」逐条审阅。对跳过的段落给出原文与你的改写建议，让用户自行决定是否手动替换。

## 已知边界

- 重写的段落中若含制表符/软换行等非 `w:t` 内容，修订重建后这些字符会丢失；含图片/域的段落已被第 2 步过滤，正常报告正文不受影响。
- 只处理文档正文顶层段落（表格内、文本框内不处理），与原实现一致。

## 排障

- 打开/保存失败或内容乱码：多为透明加密文件，转 `decrypt-office-pdf` 解密后重试。
- 「段落内容已变化」：rewrites.json 的 paraIndex/original 与文档不符，重新提取再生成。
- diff 矩阵超限（原文超长段落）：脚本自动跳过该段，属预期保护。
